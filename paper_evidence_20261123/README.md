공통 구조 (두 시스템 같음):
1. 지시 이해: Qwen3-VL-4B-Instruct가 지시 글자만 읽고 정해진 항목(JSON)으로 바꾼다. 이미지를 보지 않고, 위치·박스·좌표를 만들지 않는다.
2. 장면 인식: Grounding DINO-tiny가 후보 박스를 내고, SigLIP2 so400m이 후보를 예시 이미지(큐브, 빈 팔레트)와 비교해 점수를 매긴다.
3. 대상 결정: Python 규칙이 한다. 1위 점수 ≥ 기준, 1·2위 차이 ≥ 0.02, 점유 여부를 보고, 확신이 없으면 보류한다.
4. 좌표 변환: 박스 중심을 env2 지도 좌표(m)로 바꾼다. 물체 윗면 높이 평면으로 투영하며, 팀원 `pixel_to_map.py`를 쓴다.
5. 경로 생성: 정차 자세를 정하고(그리퍼 끝이 물체를 향함, 차체가 노란 선 안), 4방향 A*로 경로를 만든다.

공간 관계는 누가 판단하나? 코드로 확인했다.
- Qwen은 글자만 정해진 이름으로 바꾼다.
  - 예: "하역장 옆에서" → `object_near: truck_loading_bay`, "충전소 옆에" → `destination_place: charging_station`
  - 어느 물체가 하역장 옆에 있는지는 판단하지 않는다.
- "X 옆" 판단은 Python 규칙이다. 후보의 지도 좌표에서 사람이 그린 5S 구역(X)까지의 거리가 30 cm 이하이면 "옆"으로 본다.
- 이 규칙은 옮길 물체(A)에만 적용된다.
  - 도착지가 "빈 팔레트"일 때 Qwen이 뽑은 `destination_place`는 코드에서 버려진다 (`engine.py` 260–261행).
  - 그래서 논문 2.1절 예문의 "충전소 옆에"는 목적지 선택에 쓰이지 않았다.
  - 그 실행에서 고른 팔레트는 충전 구역에서 약 11 cm 떨어져 있었다. 이 거리는 기록된 좌표로 다시 계산한 값이다. 즉 결과는 맞았지만 우연이다. 2위 팔레트와 점수 차는 0.021로, 기준 0.02를 겨우 넘었다.
- 기존 시스템(논문 3.1 수치)에는 "X 옆" 규칙이 없다.
