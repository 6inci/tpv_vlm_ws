## 쓰는 방법

1. **시작 화면에서 장면 출처를 고릅니다.**
   - 저장된 사진: `/home/binci/Pictures/Calibration/map_images/` 14장 중 13장
     - `20261120_215746_view.png`는 큐브가 노란 선 밖 16 cm(작업 공간 한도 15 cm)라 로봇이 접근할 수 없습니다. 목록에서만 뺐고 원본 파일은 그대로입니다(설정 `exclude_photos`).
     - 실시간 모드의 카메라 자세 기준 사진도 `20261120_215805_view.png`로 바꿨습니다.
   - 실시간 카메라: 위쪽 전환 버튼으로 언제든 바꿀 수 있습니다
2. **사진을 고르거나, 실시간이면 "지금 장면 찍기"를 누릅니다.**
3. **작업지시를 쓰고 "경로 만들기"를 누릅니다.** 예시 버튼은 입력 칸만 채웁니다.
4. **오른쪽 "추론 과정"에서 다섯 단계가 차례로 채워집니다.**
   - 확신이 없으면 그 단계에서 **보류**하고 경로를 만들지 않습니다. 보류한 이유가 나옵니다.
5. **가운데에서 결과를 봅니다.**
   - "사진 위"와 "지도" 탭에서 옮길 것(A), 놓을 곳(B), 정차 자세(노란 선 = 그리퍼), 경로와 경유점을 봅니다. 경유점에 마우스를 올리면 지도 좌표가 나옵니다.
   - 아래 표에 구간별 경유점(x, y, 차체 방향, 회전 위치)이 있습니다.
   - "경로 파일 받기"로 전달용 묶음을 내려받습니다.

지난 결과는 주소로 다시 열 수 있습니다: `http://127.0.0.1:8765/?mode=photo&job=<작업 id>` (서버를 켜 둔 동안만).

## 지원하는 지시

| 종류 | 예 | 경로 |
|---|---|---|
| 빈 팔레트로 옮기기 | "빨간 큐브를 비어 있는 팔레트로 옮겨줘." | 출발 → 큐브 파지 정차 → 팔레트 배치 정차 |
| 장소 옆 물체 | "컨베이어 옆에 있는 물건을 빈 팔레트에 놓아줘." | 같음. 물체가 그 장소 구역에서 30 cm 안이어야 함 |
| 장소로 옮기기 | "빨간 큐브를 하역장으로 가져가." | 출발 → 큐브 파지 정차 → 장소 정차 자리 |
| 이동만 | "충전소로 이동해." | 출발 → 장소 정차 자리 |
| 장소에서 출발 | "하역장에서 출발해서 컨베이어로 가.", "하역장에서 충전소 옆으로 이동시켜줘" | 그 장소 정차 자리 → 도착 장소 |

- 장소 → 장소 이동에서 Qwen이 "하역장에서"를 출발이 아니라 "물체 옆 장소"로 넣은 사례가 있었습니다(2026-11-22 사용자 실행).
  - Python 보정으로 고쳤습니다: 옮길 물체가 없는 이동인데 물체 옆 장소만 있고 출발이 없으면, 그 장소를 출발로 봅니다. 보정하면 ① 단계 요약에 "해석 보정"으로 나옵니다.
  - ① 단계 요약에 출발 장소를 함께 보여 줍니다("출발 하역장, 도착 충전소").
  - 프롬프트를 고친 v3도 만들어 CPU에서 실제 Qwen으로 확인했지만 같은 해석이 나와 쓰지 않았습니다. 프롬프트는 `console_slots_v2b` 그대로입니다(v3 보관: `sessions/prompt_console_slots_v3_not_used.yaml`).
- 도착지의 "충전소 옆 회색 팔레트"처럼 팔레트에 붙은 장소 조건은 확인하지 않습니다. 빈 팔레트 점수로만 고릅니다.
- 출발은 사진 속 로봇 자리입니다. 15장 모두 같은 자리이고, 로봇 윗면 ArUco 마커가 3 px 넘게 움직이면 멈춥니다. 지시에 출발 장소가 있으면 그 장소의 정차 자리를 출발로 가정합니다.
- 장소의 정차 자리는 팀원 `zones.json`의 값입니다: 하역장, 컨베이어, 충전소, 소화기, 보행자. 다른 장소(선반, 사물함 등)는 정차 자리가 없어 목적지로 쓰지 않고 보류합니다.
- 이 로봇이 집을 수 있는 물체는 빨간 큐브뿐입니다(설정 `graspable_objects`).

  - 하역장은 그 자리에서 0°·180°만 되므로 그리퍼가 구역을 약 90° 비껴 봅니다. 화면과 기록에 "주의"로 표시합니다.
- 그리퍼 도달 거리와 파지 가능 여부는 실측 전입니다. 정차 자세는 "그리퍼 끝에서 물체까지 모자란 거리"만 보여 줍니다.
- Qwen이 "상자"를 "종류를 말하지 않은 물체"로 해석한 사례가 있습니다(프롬프트 예시를 보완했으나 같음). 이때는 큐브를 찾으러 가므로, 지금 장면에서는 "장소 옆" 조건에 걸려 보류됐습니다.
- 지시 문장의 다양성(바꿔 말하기, 영어 등)은 시험하지 않았습니다.
- 실시간 모드는 보정된 외부 카메라가 실험 사진과 같은 자세일 때만 경로를 만듭니다. 그 카메라로는 아직 시험하지 않았습니다.

## 화면 설계 메모

비교한 화면 유형과 가져온 것:

| 유형 | 예 | 가져온 것 | 가져오지 않은 것 |
|---|---|---|---|
| 로봇 데이터 도구 | Foxglove Studio, RViz2 | 사진과 지도를 같은 자료로 겹쳐 보기, 표시 켜고 끄기 | 패널이 빽빽한 구성, 3D 중심 화면 |
| 주행 목표 지정 화면 | Nav2 웹 대시보드 | 지도 위 경로와 경유점 | 사용자가 목표를 클릭하는 방식 (이 콘솔은 추론으로 정함) |
| 물류 로봇 관제 화면 | 창고 AMR 관제 콘솔 | 지도 중심 + 작업 상태 열, 밝은 바탕 | 여러 로봇·일정 관리 |
| 모델 데모 화면 | Gradio 데모 | 입력 하나, 결과 하나의 단순한 흐름 | 입력 폼만 있는 구성 |

- **움직임:** 오른쪽 "추론 과정"의 연결선이 단계가 끝날 때마다 바닥 테이프처럼 칠해지는 것, 진행 중 표시의 테이프 사선 두 가지뿐입니다. 동작 줄이기 설정을 따릅니다.
