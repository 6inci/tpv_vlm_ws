# 후보 보존 정책 1단계: 오프라인 (2026-11-19)

- 범위: 탐색 ROI를 제외 조건에서 우선순위로 바꾸고 Top-K로 후보를 지우지 않을 때, 기존 8장에서 큐브 후보가 검증 단계까지 남는지 확인한다. **모델 호출 0회, GPU·Qwen 미사용.** v0.2는 수정하지 않았다(코드 지문 `254cfb31da7f…` 실행 전후 동일).
- **정확도·재현율·성공률은 계산하지 않았다.** 큐브 위치는 `cube_candidate_funnel`의 AI 예비 라벨(`AI_PRELIMINARY_REVIEW`)이고, 8장은 같은 배치의 한 세션이다. 아래 숫자는 "AI가 라벨한 후보가 검증 단계까지 남은 사진 수"다.
- 근거 실행: `results/20261119_073841_retention/` (`result.json`, `01_retained_candidates.png`).

## 0. 결론

1. **8장 모두에서 큐브 후보가 검증 단계까지 남았다**(v0.2에서는 4장이 ROI에서 먼저 빠졌다). 순위는 1–6위이고, 8장 모두 v0.2의 검증 상한 8개 안에도 든다.
2. **Top-K로 지운 후보는 없다.** 검증 예산(24개)을 넘은 후보는 E1의 14개뿐이며 `BEYOND_BUDGET`으로 기록에 남아 있다.
3. **DINO와 HSV의 일치는 큐브를 가려내지 못했다.** E1에서 출처 종류 2개 이상이 일치한 후보는 큐브만이 아니다. 저장된 Qwen 답을 새 상태에 대입하면 `PROBABLE`이 3개(큐브, "irregularly shaped object", "rectangle")이고 사진 판정은 `AMBIGUOUS`다. 일치를 독립 증거 2개로 세면 안 된다는 지적과 맞는 결과다.
4. **DINO 기록은 E1에만 있다.** 나머지 7장은 색·모양(HSV) 후보만이라 "DINO·HSV 후보 유지"는 E1에서만 확인됐다. 7장의 DINO는 `NOT_AVAILABLE`이다.

## 1. 정책 (실행 전 `config.yaml`에 선언)

| 항목 | v0.2 | 이 실험 |
|---|---|---|
| 탐색 범위 | 컨베이어 ROI 안만 | 사진 전체. ROI는 정렬 키 |
| 후보 | HSV + DINO(ROI, 전체 영상 중 ROI 안) | HSV(전 사진 재계산, v0.2 파라미터 그대로) + 저장된 DINO(E1: 전체 영상 26개, ROI 13개) |
| 중복 통합 | `merge_candidates` | 같은 함수 그대로. 단 큰 탐지 박스는 병합에서 제외(아래 3항) |
| 정렬 | 출처 수, 점수, solidity | 큐브 크기 후보 먼저 → 출처 종류 수 → **ROI 안 먼저** → 점수 → solidity |
| 상한 | 8개 밖은 `not_run` | 24개까지 검증 대상, 나머지는 `BEYOND_BUDGET`으로 기록 |

검증 상태(이 단계에서는 저장된 E1 Qwen 답에만 적용): `VLM_ACCEPTED`(Qwen yes. `CONFIRMED`가 아니다) / `PROBABLE`(Qwen no, 출처 종류 ≥ 2, Qwen이 본 색이 목표 색. 불일치를 기록) / `REJECTED` / `PENDING_VERIFICATION`(Qwen 답 없음) / 사진 판정 `AMBIGUOUS`(`VLM_ACCEPTED`·`PROBABLE`이 둘 이상이면 자동 선택하지 않음). `PROBABLE`은 가상 작업계획에만 쓴다.

## 3. 개발 중 발견한 문제

- 첫 실행(`results/superseded_runs/20261119_073759_retention`)에서 전체 영상 DINO의 큰 박스(483×242 px)가 v0.2의 포함 규칙을 통해 **서로 다른 작은 후보 둘을 한 후보로 묶었다.** v0.2 병합은 ROI 안의 작은 박스를 전제로 한다. v0.2의 기존 크기 상한(`candidate_max_area_raw_px` 4000 px²)을 넘는 탐지 박스는 병합에 넣지 않고 별도 기록으로 두도록 고쳤고(E1 후보 34 → 38개), 테스트로 고정했다. 결과를 본 뒤의 수정이며, 새 임계값을 고른 것은 아니다.
- 설정 파일의 YAML 따옴표 오류로 첫 시도가 시작 전에 멈췄다(결과 폴더 없음).

## 4. 한계

- 라벨은 사람이 확인하지 않았다. 같은 배치·같은 세션 8장이다.
- 7장에는 DINO가 없다. DINO를 더하면 후보 수와 순위가 달라진다(E1: HSV만 22개 → 38개).
- 병합은 입력 순서에 따라 묶음이 달라질 수 있다(v0.2 함수의 성질). E1의 저장된 5번 후보가 이번에는 전체 영상 DINO 박스와 묶여 3순위가 됐다.
- 저장된 Qwen 답은 v0.2의 크롭에서 나온 것이다. 새 후보 박스와 IoU ≥ 0.5로 대응시켰다.
- 후보가 남는 것과 올바르게 확정되는 것은 다르다. 이 단계는 앞의 것만 본다. `PROBABLE` 규칙은 E1에서 큐브가 아닌 후보 둘도 통과시켰다.
