## 0. 먼저 읽을 결론

1. **한 번의 응답으로 의미 지도를 완성하지 못했다.** 응답이 객체 목록 중간에서 **같은 항목을 반복하는 루프**에 빠졌고, 출력 한도(9,000 토큰)에 도달할 때까지 멈추지 못했다. 그래서 **관계, 의미 영역, 목적지는 하나도 생성되지 않았다.** (이것은 "보류"가 아니라 "생성되지 못함"이다.)
2. 응답의 76개 객체 중 **서로 다른 항목은 26개**이고, 50개(`obj_27`–`obj_76`)는 마지막 주황 콘의 이름·박스를 그대로 되풀이한 것이다. 응답의 65%가 이 루프다.
3. **객체의 위치는 대체로 잘 잡았다.** 서로 다른 26개 중 상당수가 실제 물체 위에 놓인 타이트한 박스다. 이동로봇도 **독립된 객체로, 주변 적치물과 병합되지 않은 박스**로 잡았다.
4. **그러나 이동로봇을 `mobile_robot`으로 분류하지 못했다.** 이름은 `black_truck`, 분류는 `other_vehicle`이고, 근거("검은 운전실과 트레일러", "화물 적재")는 사진에 없는 내용이다. 모델 전체에서 `mobile_robot`으로 분류한 객체가 0개다.
5. 오인식이 확신과 함께 나왔다. 서로 다른 26개 중 이름이 틀린 것 4개, 바닥 표시를 객체로 적은 것 2개, 인접한 두 물체를 한 박스로 합친 것 1개이고, 모든 객체의 불확실성이 `low`였다.
6. 기존 코드와 이전 실험은 수정하지 않았다(§10).

## 2. 사용 모델 및 프롬프트

- 모델: **Qwen3-VL-4B-Instruct** 하나만 사용 (commit `ebb281ec70b0…`, bf16, greedy). 기존 로컬 모델과 worker를 그대로 재사용했고 `qwen_generate` 명령만 호출했다. 매니페스트: 로드된 모델 `['qwen']`, GPU 교체 0회, worker 로그에 DINO 흔적 0건. 사용하지 않은 것: Grounding DINO, SAM2, YOLO-World, V1/V2 검증기, A\*, ROS2, 하드웨어.
- 환경: torch 2.13.0+cu130, transformers 5.16.1, RTX 5070 Ti Laptop. 입력 3,414 토큰, 출력 **9,000 토큰(한도 도달)**, 303 s, 최대 VRAM 10.07 GiB.
- 지시문(L2): "빨간 큐브를 출하할 수 있는 적절한 장소로 옮겨줘."
- 프롬프트: **새 버전 `sm0`**, SHA-256 `0e6d89a75dbceac9…`, 5,341자, 실행 1초 전 동결(`prompt_frozen.json`). 기존 동결 프롬프트는 쓰지도 수정하지도 않았다.
  - 다섯 부분을 요청: A 개별 객체(박스, 추정 기능, 근거, 불확실성), B 이동성 분류(`mobile_robot` / `other_vehicle` / `static_equipment_or_goods` / `fixed_structure` / `uncertain`), C 관계(관찰/추론 구분), D 의미 영역(객체와 **별도의** 박스), E 목적지(제안 또는 보류).

  - 동결 전 문구 수정 3회: 테스트가 장면 정보로 읽힐 수 있는 표현(분류 정의의 장면 물체 이름 예시, "one object"/"several objects")을 잡아서 고쳤다. 첫 동결 파일(`42dfbbe7…`)은 테스트가 1건 실패한 상태에서 만들었다가 모델이 보기 전에 폐기해 `superseded/`에 남겼다. 모델 출력은 어느 문구에 대해서도 없었다.

| 6 | 의미 영역이 필요 이상으로 넓은가 | 평가 불가. 객체 `obj_8`(초록 통로)의 박스가 넓어 로봇팔 받침까지 덮은 것은 확인 |
| 7 | 자연어에 적합한 목적지를 제안했는가 | 제안 없음 |
| 8 | 확인할 수 없는 객체·관계를 생성했는가 | **예**: 로봇의 "트레일러·화물", 우하단 물체를 `red_cube`, 패널 스탠드를 `light`, 50개의 반복 항목(객체가 아님). 관계는 생성되지 않음 |

그 밖의 문제:
- **지시 위반**: "반복하지 말 것", 객체 최대 40개(76개), 바닥 표시는 객체가 아님(2개 위반), 모든 객체에서 `uncertainty_note` 필드 누락(76/76), `unverifiable_or_unclear`와 이후 섹션 전체 누락. 스키마 위반 80건이 기록되어 있다(`result.json`).
- **보정되지 않은 확신**: 틀린 이름 4개와 병합 1개를 포함해 모든 객체의 불확실성이 `low`.
- **큐브 오인**: 지시문의 "빨간 큐브"와 관련해, 실제 큐브(왼쪽 아래 회색 타일 위)는 놓쳤고 다른 빨간 물체를 `red_cube`로 적었다.
- 이 루프는 이전 실험과 같은 종류다: 이전 실험에서도 개별 객체 목록(콘, 장벽)이 반복 루프에 빠졌다(자율 의미 추론 실험의 개발 실행 v1·v2, `experiments/autonomous_semantic_reasoning/REPORT`와 `prompts.yaml` 이력). 그때는 종류별 인벤토리로 형식을 바꿔 피했지만, 이번에는 요청대로 개별 객체를 나열하게 해서 다시 나타났다.

## 9. 불확실하거나 확인하지 못한 사항

- 의미 영역, 관계, 목적지를 이 모델이 **얼마나 잘** 만드는지는 이번 응답으로 알 수 없다. 형식 실패로 시도 자체가 관측되지 않았다.
- 루프가 없었다면 나머지 섹션을 완성했을지는 `UNKNOWN`이다. (26개 객체에 해당하는 응답은 전체의 약 35%이므로 한도가 직접 원인이 아니라 루프가 원인이다. 다만 이것은 응답 길이로부터의 추정이다.)
- 이동로봇을 `mobile_robot`으로 분류하는 표현이 다른 프롬프트에서도 실패하는지 (`UNKNOWN`).
- **재현성**: greedy라 같은 입력은 같은 출력일 것으로 보이나 이번에는 1회만 실행했다.
- AI 예비 기준의 박스는 눈으로 읽은 근사값(±20 px)이다. 박스의 정밀도는 정량화하지 않았다.
- 한 장의 사진, 한 번의 실행이다. 일반화할 수 없다.

## 11. 다음 실험에서 개선해야 할 문제

(실행하지 않았다. 이번 지시가 "추론 1회"여서 두 번째 실행은 하지 않았고, 아래는 사용자 확인 후의 제안이다.)

1. **한 번의 응답으로 다섯 부분을 모두 요구하지 않는다.** 객체 목록에서 응답이 끝나 이후 섹션이 사라졌다. 호출을 나눈다: (a) 객체만, (b) **그 모델 자신의 객체 목록을 입력으로** 관계와 영역과 목적지. 둘 다 Qwen만 쓴다.
2. **반복 루프 방지**: 객체 수 상한을 호출 안에서 낮추고, 같은 박스의 반복을 Python이 감지하면 중단하고 이어서 묻는 방식(감지는 모델 출력끼리의 비교이며 장면 지식이 아니다), 또는 이미지를 타일로 나눠 타일별로 나열하게 하는 방식. 샘플링 설정 변경(반복 패널티)은 기존 worker를 수정해야 하므로 복사본으로만 한다.
3. **바닥 표시와 객체를 범주로 분리**: 표시와 영역은 의미 영역 단계에서 묻는다. 이번에는 바닥 표시 2개가 객체 목록에 들어갔다.
4. **이동로봇 분류**: `mobile_robot`/`other_vehicle` 구분을 더 직접적으로 시험할 별도 질의(로봇 주변 크롭을 모델에게 다시 보여 주는 방식은 모델 출력 위치를 쓰므로 DINO 없이도 가능)와, 사진에 없는 근거를 쓰지 못하게 하는 방법.
5. **정답 데이터**: 사람이 객체와 영역의 정답을 사전에 작성해야 위치 정밀도와 영역 일치를 정량화할 수 있다.
6. **반복 측정**: 같은 배치의 나머지 사진(8장 중 4장은 미사용)과 프롬프트 변형으로 변동성을 보고 한 장의 결과가 일반적인지 확인한다.
7. 보존한 응답으로 오프라인에서 할 수 있는 것: 26개의 서로 다른 항목만으로 객체 지도를 정리하는 것은 가능하지만, 이는 모델 출력을 가공하는 것이므로 이번 진단의 결과로 쓰지 않았다.
