# 자연어 기반 픽업·운반·배치 작업계획 통합 (E1, 2026-11-19)

명령: "컨베이어에서 생산된 빨간 큐브를 출하할 수 있는 적절한 장소로 옮겨줘." / 사진 `undistorted_25070552942982.png`(1920×1080, 왜곡 보정본).
범위: 저장된 의미 추론·후보·지도를 실제 크기 Footprint의 2D 경로계획에 연결한다. **모델 호출 0회, GPU·하드웨어 사용 없음.** 픽업·운반·배치 성공은 주장하지 않는다.
근거 실행: `results/20261119_082047_route/` (`task_plan.json`, `path_a.json`, `path_b.json`, `validation.json`, `figures/01–06`).
표기: `CONFIRMED` 저장 기록·코드로 확인 / `INFERRED` 해석 / `UNKNOWN` 미확인 / `UNVERIFIED` 물리적으로 검증되지 않음 / `PROVISIONAL` 잠정값.

## 0. 결론

1. **조건 A(예비 기준 대상)와 조건 B(보존 후보)에서 모두 경로 A·B가 생성됐고, 하나의 작업계획으로 연결됐다.** 경로 B는 경로 A의 끝점에서 시작한다. 차체 전체(35×24 cm + 변환 오차 3.5 cm/변 = 42×31 cm)가 장애물·금지 구역·주행 영역 밖·작업공간 밖을 침범한 픽셀은 생성된 경로 8개 모두 0이다.
2. **이 결과는 가정 조건부 성공이다.** 바닥 좌표는 잠정 변환(사람 확인 기준점 없음)이고 지도는 사람이 확인하지 않은 DRAFT다. 실제 치수 기반 안전성은 주장하지 않는다(`GEOMETRY_UNVERIFIED`).
3. **이전 실험의 1,014.5 px 경로(v0.2 반경 35 px)는 실제 크기 검사를 통과하지 못한다.** 공칭 35×24 cm 몸체로도 두 방향 모두 적치 구역 Z04와 겹친다. 실패로 기록했다.
4. **보수적 원형 Footprint(반경 26.1 cm)로는 경로가 없다.** 시작점에서 이미 충돌한다(시작점 여유 19.75 cm). 방향을 고정한 직사각형 검사가 필요했다.
5. **조건 B는 대상을 확정하지 않는다.** `PROBABLE` 후보 3개에 각각 조건부 계획을 만들었고 사진 판정은 `AMBIGUOUS`, 선택된 대상은 없다. 선반 위 두 후보(3·6순위)는 가장 가까운 도달 가능 위치에서도 그리퍼가 메워야 할 간격이 69–73 cm로, 큐브 후보(13.7 cm)와 크게 다르다. 이 값은 기록만 하고 선택에 쓰지 않았다.

**`AnalysisRun`은 인스턴스화하지 않았다.** 모델 호출 단계가 묶인 상태 기계라서 오프라인 재생에 쓰려면 단계 메서드 대부분을 덮어써야 하고, 그것은 사실상 재구현이다. 대신 실패 코드와 단계 상태 어휘를 재사용하고, 단계 순서는 이 실행기에서 기록했다(`task_plan.json`의 `steps`).

**의미 추론 출처 주의**: 이 명령문 그대로의 저장 Qwen 응답은 없다. 목적지는 앞부분("컨베이어에서 생산된")이 빠진 L2 문장("빨간 큐브를 출하할 수 있는 적절한 장소로 옮겨줘.")의 저장 응답(`area_5` loading dock, 근거 truck·cones·barriers)을 썼다. 목적 문구가 같아서 재사용했지만(`INFERRED`), 이 문장으로 다시 추론하려면 Qwen 호출이 필요하다.

## 2. 새로 구현한 기능 (`route_integration.py`)

- 조건 A·B 대상 입력: A는 AI 예비 라벨 박스, B는 보존 정책의 `PROBABLE`/`VLM_ACCEPTED` 후보별 조건부 계획.
- 계획 상태: `APPROACH_PLANNED` → `VERIFY_REQUIRED` → `PICKUP_ASSUMED` → `TRANSPORT_PLANNED` → `PLACEMENT_ASSUMED`. 모두 `executed: false`이고 픽업·배치 가능성은 `UNVERIFIED`다.
- 실패 코드 집계: `START_POSE_INVALID`, `NO_VALID_PICKUP_APPROACH`, `NO_VALID_PATH_A`, `NO_VALID_PLACE_APPROACH`, `NO_VALID_PATH_B`. v0.2 원래 코드는 방향별로 보존한다.
- 층별 침범 계산: 경로를 따라 움직인 차체 영역을 정적 장애물·금지 구역·주행 영역 밖·작업공간 밖과 각각 비교한다(4 px/cm).
- 비교 실험: 공칭 직사각형(여유 0), 보수적 원판(v0.2 `NavMap` 그대로).
- 이전 35 px 경로 재검사.
- 그림 6장, 테스트 16건.

## 3. 조건 A — `REFERENCE_TARGET_PRELIMINARY`

입력: AI 예비 라벨 [434, 417, 451, 432] px (사람 확인 정답·오라클이 아님). 바닥 투영 (51.5, 92.6) cm은 추정값이다. 큐브가 컨베이어 표면 위에 있어서 높이(`UNKNOWN`)만큼 시차로 어긋난다.

| 구분 | 경로 A | 경로 B |
|---|---|---|
| 방향(고정) | 0° | 0° |
| 웨이포인트 (cm) | (293,157) → (105,155) → (101,153) → (83,113) | (83,113) → (101,89) → (233,83) |
| 길이 | 236.3 cm | 162.1 cm |
| 접근점 | 픽업 (83,113) cm | 배치 (233,83) cm |
| 그리퍼가 메워야 할 간격 (공칭 몸체 ↔ 대상) | **13.7 cm** (`UNVERIFIED`) | **37.8 cm** (`UNVERIFIED`) |
| 전신 검사 / v0.2 검증기 / 침범 픽셀 | 통과 / 유효 / 0 | 통과 / 유효 / 0 |

목적지는 네 층으로 구분했다(`task_plan.json`의 `destination_layers`).
1. Qwen 의미 목적지 박스.
2. 영상에서 관찰된 하역 구획(Python).
3. 로봇 정지 위치 (233, 83) cm.
4. 배치 가능 영역 후보(구획 바닥에서 물체를 뺀 영역, `UNVERIFIED`).

큐브 쪽은 이미지 박스 → 바닥 추정 위치 → 픽업 접근점 → 향해야 할 방향(−147°, 정렬 회전 미검증) → 그리퍼 도달 가능 여부(`UNVERIFIED`)로 구분했다.

비교:
- 공칭 35×24 cm(여유 0, 보수적이지 않음): 경로 A·B 생성(방향 90°, 244.2 + 159.5 cm).
- 보수적 원판(반경 26.1 cm): `START_IN_COLLISION`으로 경로 없음.

## 4. 조건 B — 보존 후보

사진 판정 `AMBIGUOUS`, 선택된 대상 없음. 후보 38개와 상태를 원본 그대로 보존했다(테스트로 동일성 확인). `CONFIRMED`는 하나도 없다.

| 재순위 | 상태 | Qwen 크롭 판정(기존/마커 제거/주변 확대) | 위치 | 경로 A | 간격 | 경로 B |
|---|---|---|---|---|---|---|
| 1 | `PROBABLE` | no / yes / no | 컨베이어 패드 위 | 236.3 cm | 13.7 cm | 162.1 cm |
| 3 | `PROBABLE` | no / no / no | 매트 밖 선반 | 257.0 cm | 72.9 cm | 150.4 cm |
| 6 | `PROBABLE` | no / no / yes | 매트 밖 선반 | 257.0 cm | 68.9 cm | 150.4 cm |

- 모든 계획은 `CONDITIONAL_ON_CANDIDATE`다. 3·6순위는 같은 선반 위라 접근점과 경로가 같다(그림 06에서 겹쳐 보인다).
- 세 후보 모두 확인된 컨베이어 박스에서 150 px(v0.2 `near_px`) 이내라, v0.2의 "컨베이어 근처" 규칙으로는 구분되지 않는다(정보로만 기록).
- **설계상 성질**: 접근점은 그리퍼 도달 거리를 가정하지 않고 "도달 가능한 가장 가까운 위치"로 고른다. 그래서 대상이 멀어도 실패가 아니라 큰 간격으로 나타난다. 간격이 몇 cm 이상이면 실패인지는 그리퍼 도달 거리가 측정되어야 정할 수 있다.

## 5. Footprint 기반 충돌 검증

- 차체: 사용자 값 35×24 cm(바퀴 포함 여부 `UNKNOWN`) + 바닥 변환 독립 검사 최대 편차 3.5 cm/변 = 42×31 cm. 각 경로에서 방향을 고정한다(메카넘 병진). 0°와 90°를 모두 계획했다. 동역학은 검증하지 않았다.
- 계획 단계: 자유 영역을 직사각형으로 침식해, 몸체 전체가 들어가는 중심만 유효로 둔다.
- 독립 검사: cm 다각형에서 다시 래스터화한 지도 위에서 0.25 cm마다 몸체를 검사한다. 대각선 이동이 모서리를 깎으면 이 검사에서 잡힌다(합성 모서리 테스트로 확인).
- 이전 35 px 경로 재검사:

| 몸체 | 방향 | 결과 | 첫 위반 위치 (cm) | 정적 장애물 침범 |
|---|---|---|---|---|
| 35×24 | 0° | 실패 | (232.3, 149.5) | 5,379 px (약 336 cm²) |
| 35×24 | 90° | 실패 | (279.7, 154.5) | 8,592 px |
| 42×31 | 0° | 실패 | (263.0, 152.8) | 10,034 px |
| 42×31 | 90° | 실패 | (293.1, 155.9) | 16,076 px |

  이 경로는 Z04 아래 가장자리를 따라가다가 Z03·Z04 사이 틈(약 43 cm)을 지나는데, 실제 크기의 몸체는 둘 다 걸린다.
- 여유: 직전 실험의 여유 곡선 기준으로 변당 4.5 cm까지 늘려도 A·B가 유지되고, 5.0 cm에서 시작점이 맞지 않는다.
- 제자리 회전(외접원 26.1 cm)은 시작점(여유 19.75 cm)과 픽업 접근점(22.75 cm)에서 불가하다. 큐브를 향한 방향 정렬은 검증되지 않았다.

## 8. 다음 단계 (작업 맥락 기반 소형 객체 선택)

- **가장 중요한 문제: 대상이 `AMBIGUOUS`이고 정답 확인이 없다.** 계획은 연결되지만 무엇을 집으러 가는지는 아직 규칙(재순위 1위)이다. 다음 연구의 첫 입력으로 8장의 큐브 라벨을 사람이 확인해야 한다.
- 이번에 기록된 단서:
  - 출처 관계(`conveyor`, `produced_by`): 규칙 파서로 추출됨.
  - 컨베이어와의 거리: 세 후보 모두 150 px 이내라 구분되지 않음.
  - 도달 가능 위치에서의 간격: 13.7 cm 대 69–73 cm로 크게 다름. 기하에서 나오는 작업 맥락 단서이지만, 그리퍼 도달 거리가 측정되기 전에는 판정 기준이 될 수 없다.
- 이 단서들을 미리 선언한 순위 규칙으로 8장에 적용하고, 오수락 건수와 함께 기록하는 것이 다음 실험의 최소 범위다.
- 물리적 주장을 하려면 별도로 바닥 기준점 확인과 로봇 실제 외곽 치수가 필요하다.
