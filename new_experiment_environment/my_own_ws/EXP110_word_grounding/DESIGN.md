## 0. 연구 전체에서 이 실험의 위치

- 연구 목표는 가장 정확한 detector를 고르는 것이 **아니다**. 객체 탐지 결과가 VLM의 작업환경 맥락 이해에 어떤 영향을 주는지 검증하는 것이다. 최종적으로는 목적지 추론과 경로계획이 개선되는지 본다.
- 단계: **EXP110 객체 단어 찾기** → 구역·관계 맥락 이해 → 목적지 추론 → 화면상 경로와 지도 → MCP task 분해.

## 1. 질문

- **주 질문**: 영어 단어(구) 하나를 줬을 때, detector 후보를 함께 쓰는 Qwen(C6)이 Qwen 단독(C1)보다 해당 물체를 **모두, 그리고 그것만** 더 잘 찾는가. 두 조건 모두 사전 라벨 없이 원본 사진만 본다.
- **부 질문**
  - 한국어 질의에서도 같은 경향이 나오는가 (별도 보고)
  - 동의어와 속성(색, 크기)에 따라 성능이 달라지는가
  - 실패가 detector 단계에서 생기는가, Qwen 선택 단계에서 생기는가 (C6 실패 분해)
  - detector 단독 성능은 어떤가 (C2–C5, 기준선 및 진단)
- **범위 밖**: 구역, 관계 표현("A 옆의 B"), 경로, world 좌표 (다음 실험).

## 4. 정답(answer key)

- 사람이 `tools/annotate.py`로 그린다. **모델 출력을 초안으로 쓰지 않는다.**
- 이전 배치의 정답 복사(`c`)는 허용한다. 단, 옮긴 물체는 반드시 다시 그린다.
- 박스는 보이는 부분의 외곽에 맞춘다.
- **정답 기준 v2 (사용자 승인 2026-11-14, 채점을 한 번도 하기 전에 확정)**
  1. registry class에 해당하는 **식별 가능한 물체는 모두 정답**으로 기록한다. 드럼통 4묶음, 박스 더미, IBC 아래 팔레트도 `pallet`으로 기록한다.
  2. 작업 역할(출발 팔레트, 도착 팔레트)은 정답에 넣지 않는다. 사진별 과제 파일로 따로 두고 의미 추론 실험에서 쓴다.
  3. `ignore`는 경계를 정할 수 없는 경우에만 쓴다. v1의 드럼 팔레트 ignore와 안내문 ignore는 폐기한다. 안내문 위의 예측은 오답(FP)이 된다.
  4. 트럭 짐칸의 박스는 `loose_box`로 기록한다. "상자/박스/cardboard boxes/cartons" 질의에서는 정답이고, "박스 더미/stack of boxes" 질의에서는 ignore이다.
  - v1과의 차이: v1은 드럼 팔레트, 안내문, 트럭 짐칸 박스를 ignore로 두었다. 그 결과 잘 찾는 모델이 오히려 감점되고, 안내문 오탐은 숨겨지는 편향이 있었다.
- **단위 규칙**
  - 드럼통: 팔레트 위 묶음 1개 = 박스 1개 (variant = 색). 그 아래 팔레트는 별도의 `pallet` 박스로 그린다.
  - 블록: 큐브 1개 = 박스 1개 (variant = 색).
  - 로봇(21): 이번 데이터에는 없다.
- 질의 ID와 문장은 v1과 같다. 상자 관련 질의 6개(q046–q051)의 정답 범위만 바뀌었다. 그래서 run01의 모델 출력은 그대로 유효하다. 단, run01의 `_snapshot`은 v1 질의를 담고 있어서 run01에 조건을 추가로 실행하는 것은 거부된다.
- **채점 대상**: 도구에서 `f`를 눌러 `DONE`으로 표시한 정답만 채점한다(`tools/score.py`).

**C6의 detector는 미리 정하지 않는다.** dev에서 아래 후보를 모두 시험하고 §9 규칙으로 하나를 고른다.

- **C6-pf**: YOLOE-26s-pf 후보. 질의와 무관한 후보이다.
- **C6-q[DINO / YOLOE-text / YOLO-World / Florence]**: 질의 문자열로 낮은 임계값 검출을 해서 후보를 만들고, Qwen이 확인·선택한다.

**어휘 규칙 ("사전 라벨링 없이" 주장을 지키기 위함)**: detector에는 **사용자 질의 문자열만** 주거나(C6-q), **아무것도 주지 않는다**(C6-pf). registry의 물체 목록을 detector나 Qwen에 주지 않는다.

**언어 비교 제외**: YOLOE-26s-pf는 텍스트를 받지 않으므로 단독 조건으로는 언어 비교에서 제외한다(사용자 결정). C6-pf에서는 질의를 Qwen이 해석하므로 언어 비교에 포함된다. 한국어 질의를 C6-q에 넣으면 detector에 한국어가 그대로 들어가는데, 이는 detector 언어 한계로 별도 표기한다.

## 7. 지표

- **매칭**: 질의 하나와 이미지 하나마다 Hungarian 매칭(IoU ≥ 0.5). ignore 박스와 IoU ≥ 0.5인 예측은 채점에서 뺀다.
- **주 지표 = 질의 성공률**: 정답이 모두 매칭되고 남는 예측이 0개이면 성공이다. Q5는 예측이 0개이면 성공이다.
- **보조 지표**
  - 개체 recall과 precision
  - 중심점 적중 (작은 물체용)
  - 개수 일치 여부
  - Q5 환각률
  - 질의당 지연시간, 최대 VRAM
- **C6 실패 분해** (detector를 붙인 효과를 직접 보여 주는 지표)
  - ① 정답 박스가 후보에 없음 → detector 단계 실패
  - ② 후보에 있는데 Qwen이 고르지 않음, 또는 다른 것을 고름 → Qwen 선택 실패
  - 후보 recall도 함께 보고한다.
- **C2–C4 실패 분해**: conf 0.01로 모든 박스를 저장한다. 후보 없음 / 임계값 / 이름으로 나눈다.
- **과제 핵심 물체(블록, 소형 팔레트, 라바콘)**는 결과를 따로 표로 낸다.

## 8. 통계

- 분석 단위는 (질의, 배치) 쌍이다.
- 신뢰구간은 질의 단위 cluster bootstrap으로 구한다. 고정 물체 질의는 배치끼리 상관되기 때문이다.
- **주 비교 (사전 고정)**: test 세트 영어 질의에서 C6* vs C1. C6*은 dev에서 고른 변형이다.
  - 같은 (질의, 배치) 쌍에서 McNemar exact 검정을 하고, 성공률 차이의 cluster bootstrap 신뢰구간을 함께 낸다.
- **부 비교**: 한국어 C6* vs C1, 그리고 C2–C5 비교. 탐색적이며 Holm 보정을 한다.
- test 배치 수는 dev에서 C1과 C6* 성공률을 추정한 뒤 검정력 계산으로 정한다.

## 9. dev 결정 규칙과 감도 분석

- **C6 detector 선택**: dev 영어 질의 성공률(end-to-end)이 가장 높은 변형을 고른다. 차이가 2%p 이내면 지연시간이 짧은 쪽을 고른다. 고른 결과와 근거는 test 전에 이 문서에 기록한다.
  - 후보 recall이 아니라 최종 성공률로 고르는 이유: 연구 질문이 "Qwen의 결과가 좋아지는가"이기 때문이다.
- **임계값**: C2–C4와 C6-q의 후보 임계값은 dev에서 사후에 바꿔 보며 고른다(재실행 없음).
- **입력 해상도**: 640 / 1280 / 1920으로 C2–C4를 재실행한다.
- **Qwen 입력 픽셀 수**: 기본 / 최대.
- **모델 크기**: 이번 pilot에서는 기존 모델만 쓴다. 단, Florence-2 base/large는 둘 다 설치되어 있으므로 비교한다.
  - 추가 가중치(DINO base, YOLOE m/l, Qwen3-VL-2B)는 **보류**한다(사용자 결정).
  - 다음 결과를 보고 추가 여부를 결정한다: 기존 모델 성능, 추론 시간과 실제 VRAM, 작은 물체와 가려진 물체의 탐지 한계, 최종 모델 선정에 크기 비교가 필요한 정도.
- 논문에는 test 결과를 본문에, 감도 분석을 부록에 쓴다.
