### 1.1 정보 제공 조건 (사용자 지시 2026-11-15: J-vlm과 J-geo의 정보 조건을 구분)

| 정보 | J-vlm | J-geo (oracle) | J-geo (detected) |
|---|---|---|---|
| 질의 문장 | 사진과 함께 받음 | 사진 없이 문장만 받아 구조로 정리 | 같음 |
| 후보 팔레트 위치 | 번호 박스로 사진에 그려짐 | 정답 박스 좌표 | EXP111 예측 박스 좌표 |
| 기준 물체(트럭, 충전기) 위치 | **표시 없음. 사진에서 스스로 찾아야 함** | 고정물 정답 박스 (= M-map 사전 지도 대용) | 같음 |
| 팔레트 상태(적재/빈, 블록 색) | **사진에서 스스로 판단** | 정답 상태 | EXP111 예측 상태 |
| 판단 주체 | Qwen (사진) | Python 규칙 (픽셀 간격, 임시) | 같음 |

- 해석상 주의
  - oracle 조건에서 J-geo는 정답 상태와 정답 기준 위치를 받는다. 따라서 state 묶음의 J-geo 결과는 **문장 해석이 맞았는지만** 보여 준다. 상태를 판단하는 능력은 재지 않는다.
  - 상태 판단을 같은 출발선에서 비교하려면 detected 조건(J-geo가 EXP111 예측 상태를 받음)을 봐야 한다.
  - spatial 묶음에서 J-geo가 기준 위치를 받는 것은 M-map 설계 그대로다(고정물은 지도에 있음). J-vlm에게는 지도를 주지 않는다. 이 차이는 의도한 설계이며, 결과에 함께 적는다.

  - 그래서 이 조건만 먼저 실행한다.
- 해결안 (사용자 선택)

| 안 | 내용 | 장점 | 단점 |

## 3. 판정

- 항목마다 결과를 다음 중 하나로 매긴다 (사용자 지시 2026-11-15).

| 결과 | 뜻 |
|---|---|
| correct_target | 정답이 있고, 맞는 대상을 고름 |
| wrong_target | 정답이 있는데, 다른 대상을 고름 |
| missed | 정답이 있는데, 고르지 않음(보류) |
| correct_abstain | 정답이 없고(없음 / 확인 불가), 올바르게 보류 |
| false_select | 정답이 없는데, 어떤 대상을 고름 (잘못된 대상 선택의 한 종류) |
| invalid | 출력 형식 오류: JSON 아님, 스키마 위반, 후보에 없는 번호 |

- 잘못된 대상 선택(wrong_target + false_select)을 따로 본다. 로봇이 엉뚱한 곳으로 가는 위험과 직결되기 때문이다.
- 표본이 24개 항목뿐이고 정답이 초안이므로, 결과는 **가능성 확인**으로만 쓴다.
- 정답 초안이 바뀌면 `--rescore`로 모델 출력을 다시 채점한다 (모델을 다시 부르지 않음).

## 3a. 진단 실행 D1: 번호 상자 색 (실행 전에 기록, 2026-11-15 14:10)

- 관찰 (oracle 첫 실행)
  - J-vlm 번호 상자는 EXP110 C6 팔레트를 그대로 쓴다. 1번 = 빨강, 2번 = 하늘색이며, 이는 블록 색(빨강, 파랑)과 겹친다.
  - P01 e05 "파란 블록": 하늘색 상자를 두른 빈 팔레트 2를 골랐다.
  - P03 e04 "블록 있는": 빨간 상자를 두른 빈 팔레트 1을 골랐다.
- 가설 H-D1: 이 두 오답은 번호 상자 색이 블록 색처럼 보여서 생겼다.
- 방법: oracle 조건, 같은 후보·프롬프트·모델로, 번호 상자만 흰색 한 가지로 그려 다시 실행한다 (`--overlay neutral`). 다른 것은 바꾸지 않는다.
- 예측
  - H-D1이 맞다면 위 두 항목이 정답으로 바뀐다.
  - e03 "빈 팔레트" 보류(4/4)는 색과 관계가 적어 크게 바뀌지 않을 것이다. 바뀌지 않으면, 상태 판단 약점은 상자 색이 아니라 해상도나 개념의 문제라는 근거가 된다.
- 결과는 첫 실행을 대체하지 않는다. 둘 다 보고한다. 이 진단으로 J-vlm 설정을 dev에 맞춰 고르지 않는다. 정식 E3a의 상자 색은 새 촬영 전에 따로 정한다.

## 5. J-gate 탐색 (사용자 승인 2026-11-15, 저장된 출력만 사용, 모델 재호출 없음)
