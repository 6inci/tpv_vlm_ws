## 0. 연구의 주 작업 (사용자 정의)

> 고정된 외부 RGB 영상에서 자연어 작업지시를 해석하고, 객체의 상태와 공간 관계를 활용하여 올바른 작업 대상 및 목적지를 선택한 후, 이미지 기반 경로계획에 연결하는 것.

위험도는 **목적지 선택 결과**로 판단한다. 기준은 세 가지다:
- 올바른 선택
- 잘못된 선택
- 판단 보류

블록 파지·운반, Nav2 주행, 물리적 충돌은 현재 평가 범위가 아니다.

## 1. 평가 단위 (확정)

- 주 평가: 새 dev 8배치의 소형 팔레트 16개, 프레임 0.
- 프레임 1–2: 반복성만 본다. 독립 표본으로 세지 않는다.
- 독립 단위: 배치 8개. 통계는 배치 단위로 다시 뽑는다.
- "정답": 프레임 0의 빈/적재 상태가 맞음.
  - 형식 오류는 정답이 아니다. 전체 정확도에서도 정답으로 세지 않는다.

## 2. 상태 오판 A, B (확정)

| 이름 | 정의 | 목적지 선택에서 생길 수 있는 일 |
|---|---|---|
| A (E1) | 실제 빈 팔레트 → 적재로 판단 | 경우에 따라 다르다: 잘못된 선택, 보류, 영향 없음 (§4) |
| B (E2) | 실제 적재 팔레트 → 빈으로 판단 | **적재된 팔레트를 비어 있다고 판단해 잘못된 목적지로 선택할 가능성**이 있다. 경우에 따라 보류나 영향 없음이 될 수도 있다 (§4) |

- 형식 오류는 A, B에 넣지 않고 E7로 따로 기록한다.

## 3. dev 선별 규칙과 형식 오류 점검

### 3.1 규칙 (v3 확정 내용)

- 순개선 net = (확대 조건에서 프레임 0 상태가 맞은 팔레트 수) − (Z-full의 같은 수)
- k = 3
- Z-crop, Z-both 중 최대 하나를 고른다. 우선순위:
  1. B가 늘지 않음 (v4 보완안: §3.3)
  2. net ≥ 3
  3. 둘 다 통과하면 net이 큰 쪽
  4. net이 같으면 호출당 추론 시간 중앙값이 짧은 쪽
- 둘 다 통과하지 못하면 고르지 않는다.
- dev 선별일 뿐, 가설 입증이 아니다. test 최종 기준은 test 전에 따로 정한다.

### 3.2 형식 오류가 유리하게 작용할 수 있는 곳 점검 (사용자 지시)

| 위치 | 현재 처리 | 형식 오류로 유리해질 수 있나 | 조치 |
|---|---|---|---|
| net (정답 수) | 형식 오류 = 정답 아님 | 아니다. 형식 오류가 늘면 net이 줄어든다 | 없음 |
| **B 가드** (v3) | 적재 팔레트의 형식 오류는 B가 아니라 E7로 센다 | **그렇다.** 적재 팔레트에서 "빈" 대신 형식 오류를 내면 B가 줄어 가드를 통과하기 쉬워진다 | **§3.3 보완안** |
| 동률 시 추론 시간 | net이 같은 조건끼리만 비교 | 거의 없다. 반복 생성은 오히려 느려진다 (smoke에서 상한 64까지 생성) | 없음 |
| 목적지 선택 분석 (보고만, 선별에 안 씀) | 형식 오류 팔레트는 "상태 모름"으로 선택에서 뺀다 | 보고에서 **더 안전해 보일 수 있다.** 오선택이 보류로 바뀔 수 있기 때문이다 | E7 수와 E7의 최종 결과(§4)를 목적지 결과 옆에 함께 보고한다 |
| B-rule 기준선 | 블록 질의 하나의 형식 오류는 그 질의의 박스만 뺀다 (EXP111 s4 규칙) | 기준선이며 선별 대상이 아니다. 다만 박스가 빠져 "빈"이 될 수 있다 | 블록 질의 형식 오류 수를 따로 보고한다 |

### 3.3 v4 보완안: B 가드 (새 dev 실행 전 제안, 사용자 확인 필요)

| | 내용 |
|---|---|
| v3 | 확대 조건의 B 수 ≤ Z-full의 B 수 |
| **v4** | 확대 조건의 (B 수 + 적재 팔레트의 형식 오류 수) ≤ Z-full의 같은 수 |

- 이유: 적재 팔레트를 적재로 확인하지 못한 경우를 원인(빈으로 판단, 형식 오류)과 관계없이 함께 센다. 그래서 형식 오류로 B 가드를 피해 갈 수 없다.
- 그 밖에 바뀌는 것: 없음. net, k, 우선순위, 동률 규칙은 그대로다.
- 적용 시점
  - 새 dev 결과가 아직 없으므로, 어떤 결과도 이 보완에 영향을 주지 않았다.
  - 우선순위 3단계(최종 고정)에서 사용자가 v3과 v4 중 하나를 확정한다.
  - 코드에는 v4가 들어 있다 (`tools/h_zoom_score.py`). v3 코드는 `history/h_zoom_score_v3_2026-11-15.py`에 보존했다.

## 4. E1–E7: 오류 유형과 최종 목적지 결과를 나눠 기록 (v4)

### 4.1 두 층

| 층 | 무엇을 기록하나 | 단위 |
|---|---|---|
| 오류 유형 (인식 단계) | 팔레트마다 E1–E7 중 어떤 판단 오류가 있었나 | 팔레트 |
| 최종 목적지 결과 (선택 단계) | 그 오류가 목적지 선택을 실제로 어떻게 바꿨나 | 오류 팔레트 × 목적지 질의 |

- 최종 결과는 오류 유형에 미리 붙이지 않는다. **실제로 측정한다.**
- 측정 방법
  1. 오류가 있는 팔레트 하나만 정답으로 바꿔 같은 선택을 다시 계산한다.
  2. 결과가 같으면 → **영향 없음**
  3. 결과가 다르고, 실제 결과가 "잘못된 선택(오답 / 정답 없는데 선택)"이면 → **잘못된 목적지 선택**
  4. 결과가 다르고, 실제 결과가 "보류(놓침)"이면 → **보류 = 안전한 실패**
     - 사용자 정의: 오류를 감지하고 판단을 보류하면 안전한 실패다.
  5. 그 밖의 경우 → 기타 (기록)
- 파일: 채점 결과의 `error_consequences.json`, 요약의 `error_to_destination`.

### 4.2 E1–E7 (식별자 유지)

| ID | 오류 유형 정의 (인식 단계) | 발생 조건 | 가능한 최종 결과 (측정) | 설명 근거 (주 작업 기준) |
|---|---|---|---|---|
| E1 | 실제 빈 팔레트를 적재로 판단 (= A) | 슬랫 무늬·그림자·주변 물체를 블록으로 봄. 확대 이미지 안의 옆 바닥 블록. B-rule의 일반 질의(block, cube) | 잘못된 선택 / 보류 / 영향 없음 | 반드시 잘못된 행동은 아니다. "블록 있는 팔레트"에서는 오선택이 될 수 있다. "빈 팔레트"에서는 정답 후보가 빠져 "없음"(보류)이 되거나, 다른 팔레트가 남아 오선택이 될 수 있다 |
| E2 | 실제 적재 팔레트를 빈으로 판단 (= B) | 블록이 작게 보임 (전체 이미지에서 0.5–0.8토큰), 블록 일부만 보임 | 잘못된 선택 / 보류 / 영향 없음 | **적재된 팔레트를 비어 있다고 판단해 잘못된 목적지로 선택할 가능성.** 다른 빈 팔레트가 함께 있으면 "모호"(보류)가 될 수 있다 |
| E3 | 적재로 맞게 본 팔레트의 색 집합이 틀림 | 빨강/파랑 혼동, 블록 하나만 봄 | 잘못된 선택 / 보류 / 영향 없음 | 색 지정 질의("파란 블록")의 선택이 바뀐다 |
| E4 | 옆 바닥 블록을 팔레트 위로 보고함 (진단용, E1·E3과 겹침) | 도전 조건(D07, D08) | 잘못된 선택 / 보류 / 영향 없음 | 적재 관계 오류. E1이나 E3를 통해 선택에 영향을 준다 |
| E5 | 팔레트가 아닌 것을 팔레트로 보고 상태를 줌 | detected 후보 전용 (이번 dev에서는 실행하지 않음) | 잘못된 선택 / 보류 / 영향 없음 | 팔레트가 아닌 물체가 목적지로 선택될 수 있다 |
| E6 | 실제 팔레트를 찾지 못함 | detected 후보 전용 (이번 dev에서는 실행하지 않음) | 잘못된 선택 / 보류 / 영향 없음 | 누락을 감지해 보류하면 안전한 실패다. 관계 질의에서 남은 다른 팔레트가 선택되면 잘못된 목적지 선택이다 |
| E7 | 출력 형식 오류 (해석 불가) | JSON 아님, 키 없음, 반복 생성으로 잘림 (smoke Z-both 1건) | 잘못된 선택 / 보류 / 영향 없음 | 형식 검사로 감지되어 그 팔레트는 "상태 모름"이 된다. 선택이 보류되면 안전한 실패다. 다른 팔레트가 유일한 후보가 되어 선택되면 잘못된 목적지 선택이다 |

- v3과 비교: 식별자와 인식 단계 정의는 그대로다.
  - 바뀐 것: 고정 성격 표기("잘못된 행동", "안전한 실패")를 지웠다. 측정한 최종 결과로 대신한다.
  - 바뀐 것: E2 근거를 물리 충돌에서 목적지 오선택으로 바꿨다.
  - v3 표는 `history/CRITERIA_REVIEW_v3_2026-11-15.md`에 있다.
- selftest 예 (가짜 데이터)
  - 같은 B(E2) 오류가 한 배치에서는 잘못된 선택 2회, 보류 1회, 영향 없음 1회였다.
  - 다른 배치에서는 보류 4회였다.
  - 같은 오류 유형이라도 결과는 배치 구성에 따라 다르다.

## 5. 목적지 선택 분석

- 질의 4개: 빈 팔레트, 블록 있는 팔레트, 파란 블록 팔레트, 빨간 블록 팔레트
- 배치 8개 × 4 = 32개 결과
- 결과 분류: 올바른 선택 / 잘못된 선택 / 놓침(보류) / 올바른 보류 / 정답 없는데 선택
- 정답 쪽 선택: 사람이 쓴 관계표의 블록 위치에서 나온 상태로 계산한다. 상태 조건만 있고 거리 상수는 없다.
- E7 수와 함께 보고한다 (§3.2).
