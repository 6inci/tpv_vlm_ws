# EXP112 H-zoom 판정 기준 검토안 — 2026-11-15

- 상태: **사용자 검토 대기. 아무것도 확정하지 않았다.** 선택이 끝나기 전에는 새 dev에서 실행하지 않는다.
- 판정은 세 층으로 나눈다. 층마다 쓰는 후보 출처가 다르다.

| 층 | 묻는 것 | 후보 출처 | 성격 |
|---|---|---|---|
| 1. 수행 완료 | 등록한 대로 실행했는가 | oracle, detected | 실험 절차 |
| 2. 가설 지지 | 확대가 상태 판단을 낫게 하는가 | **oracle** (탐지 오류 제외) | 진단 |
| 3. 시스템 충분성 | 실제 파이프라인에서 쓸 만한가 | **detected** | 시스템 결과 |

- 층 1이 끝났다고 층 2, 3이 성립하는 것은 아니다. 보고서에서 각각 따로 적는다.
- 데이터: 새 dev 8배치, 팔레트 16개 (기본 12, 도전 4). 주 평가는 프레임 0이다.

## 1. 수행 완료 기준 (제안)

| # | 조건 |
|---|---|
| 1 | Z-full, Z-crop, Z-both, B-rule을 등록한 설정(sha256)으로 각 1회 실행 |
| 2 | 원문 응답과 MANIFEST 저장. 형식 오류는 오답으로 센다 |
| 3 | 채점을 저장된 원자료에서 다시 계산할 수 있음 |
| 4 | oracle과 detected를 섞지 않고 따로 보고 |

## 2. 가설 지지 기준 (oracle, 하나를 고르거나 수정)

주 지표: 빈/적재 상태 정확도 (팔레트 16개)

| 안 | 규칙 | 장점 | 단점 |
|---|---|---|---|
| A. 판정 없이 기술만 | 조건별 맞은 수와 짝 비교(같은 팔레트에서 갈린 수)만 보고 | 표본이 작은 것을 정직하게 반영 | "지지/비지지" 결론이 없어 다음 단계 결정이 사람 판단에 맡겨진다 |
| B. 상대 기준 | 아래 세 조건을 모두 만족하면 지지 (k는 사용자 결정, 예: 3) | 결론이 분명하다 | k가 임의다 |
| C. B + 색 기준 | B에 더해, 색 완전 일치 수가 Z-full보다 적지 않음 | 블록 색까지 본다 | 조건이 많아 지지되기 어렵다 |

- 안 B의 세 조건 (Z-crop 또는 Z-both 중 더 나은 쪽 기준)
  1. 상태 정확도가 Z-full보다 k개 이상 높다.
  2. 짝 비교에서 "확대 조건만 맞음"이 "Z-full만 맞음"보다 많다.
  3. 도전 조건의 바닥 블록 오판이 Z-full보다 많지 않다.

- H-zoom2 (Z-both가 적재 관계에 낫다)
  - 도전 조건 팔레트 4개에서 바닥 블록 오판 수를 비교한다.
  - 수가 너무 적어 판정하지 않고 **기술만 하는 것을 추천**한다.
- H-zoom3 (확대가 바닥 블록을 위로 오판하게 만든다)
  - 같은 4개로 기술만 한다.
- 우연 수준 참고: 항상 한쪽으로 답하는 B-const의 정확도를 함께 적는다. 새 dev의 빈/적재 비율로 정해진다.
- Claude 추천: **B (k = 3)**
  - 16개 중 3개 차이는 약 19%p다.
  - dev는 탐색이므로, 같은 규칙을 test(팔레트 32개)에서 다시 확인하는 조건으로 쓴다.
  - k를 정하는 것은 평가 기준 결정이므로 사용자가 정한다.

## 3. 시스템 충분성 기준 (detected, 하나를 고르거나 수정)

| 안 | 규칙 |
|---|---|
| S0. 지금은 정하지 않음 | dev 결과를 본 뒤가 아니라, **test 실행 전**에 따로 정한다. dev에서는 숫자만 보고 |
| S1. 배치 단위 | 배치의 모든 팔레트(오탐 포함 처리)가 상태와 색 모두 맞은 배치 수가 기준 이상 |
| S2. 팔레트 단위 | 실제 팔레트의 상태 정확도가 기준 이상이고, 오탐 팔레트를 "적재"로 판단한 수가 기준 이하 |

- Claude 추천: **S0.**
  - detected 결과는 EXP111 탐지 품질에 크게 묶여 있다 (EXP120 detected에서 확인).
  - 새 dev에서 EXP111 자체의 결과를 먼저 보고, test 전에 기준을 정하는 것이 순서다.
- detected 조건을 실행할지는 AGENTS 예외 승인과 함께 결정한다 (`DESIGN.md` §8).
