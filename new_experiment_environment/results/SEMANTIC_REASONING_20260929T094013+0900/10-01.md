## 계획된 단계와 실제 완료 상태

[RUN_PLAN.md](RUN_PLAN.md)의 다섯 단계는 다음과 같다.

1. 기존 Qwen/DINO/YOLO/SAM2/geometry 산출물을 읽기 전용으로 재사용한다.
2. YOLO-World와 Grounding DINO에서 세 가지 통제된 동의어 시험을 수행한다.
3. structured, Qwen, DINO, YOLO 및 diagnostic-augmented context에 대해 Qwen semantic grounding을 수행한다.
4. 기존 synthetic-only homography를 사용해 목표 픽셀을 투영한다.
5. 오버레이, 실패 분리, 사람 검증 자료, 향후 실험 계획 및 최종 보고서를 만든다.

실제 수행 상태는 다음과 같다. 15개 테스트 전체에 대한 structured-context Qwen 추론은 회수됐다. Qwen의 source-specific generation은 15-task/5000-token, 8-task/3200-token, 4-task/1600-token 범위로 세 번 제한 시도했으나 완전한 응답이 반환되지 않았다. 그 결과 Qwen, Grounding DINO, YOLO-World source별 semantic end-to-end 응답은 전부 실패 상태로 저장됐고, diagnostic-augmented 응답은 추가 실행되지 않았다. 양 detector의 동의어 시험은 세 종류 모두 완료됐다. synthetic homography 투영, semantic-region 자료, target 자료, 오버레이, 오류 분리, 사람 검증용 양식 및 미래 실험 계획은 파일로 남아 있다.

## Structured-context 입력과 프롬프트

[02_structured_context/PROMPT.txt](02_structured_context/PROMPT.txt)는 객체 검출을 최종 답이 아닌 근거로 취급하고, object bbox와 semantic region, obstacle/no-go 및 최종 robot goal을 구분하도록 지시한다. Loading/Storage/Work/Material area는 객체 조합과 명시적 공간 관계를 이용하고, supporting_objects는 입력 context의 객체 ID만 사용하며, 근거가 없거나 모호한 경우 `ABSTAIN` 또는 `AMBIGUOUS`와 null target을 반환하도록 요구한다. 응답 형식은 JSON이며 `task_id`, 상태, semantic region, supporting object ID, relation, polygon, pixel target, support level, evidence summary를 포함한다. chain-of-thought 출력은 금지되어 있다.

실제 구조화 문맥에는 truck, pallet, box, rack, workbench, cart, drum 등 객체에 `q_###` 식별자가 붙어 전달됐다. 이후 결과는 특히 트럭 `q_001`, 팔레트 `q_002`~`q_004`, rack `q_021`~`q_022`, workbench `q_023`, cart `q_024`, drum `q_025`~`q_028`을 참조한다. 원문 전체의 문맥과 프롬프트는 해당 파일에서 확인할 수 있다. 모델의 원시 응답은 [MODEL_RAW.txt](02_structured_context/MODEL_RAW.txt), 결과 상태는 [RESULT.md](02_structured_context/RESULT.md), 추론 시간은 [runtime.json](02_structured_context/runtime.json)에 보존됐다.

structured-context 추론은 `Qwen/Qwen3-VL-4B-Instruct`, `cuda:0`, Python `3.10.20`에서 실행됐다. 모델 로드 공유 시간은 `6.811807372999965`초, inference는 `448.1507005619999`초, 단계 총 시간은 `448.3538552360001`초, `max_new_tokens`는 5000이다. 구조화 결과 상태 문서는 `PASS`, 15/15 예측 회수로 표시하지만 semantic ground truth가 없어 정확도를 주장하지 않는다.

Qwen source-specific 결과 파일인 [qwen/RESULT.md](03_end_to_end/qwen/RESULT.md)와 [qwen/predictions.json](03_end_to_end/qwen/predictions.json)은 status `BLOCKED`이며 15건 모두 `FAILED`, semantic region/객체/관계/목표는 null 또는 빈 배열이고 validation error는 `BLOCKED_AFTER_THREE_QWEN_GENERATION_ATTEMPTS`다. 가짜 예측은 만들지 않았다. Qwen 본 prompt와 축소 시도 prompt는 [PROMPT.txt](03_end_to_end/qwen/PROMPT.txt), [PROMPT_attempt01.txt](03_end_to_end/qwen/PROMPT_attempt01.txt), [PROMPT_attempt02.txt](03_end_to_end/qwen/PROMPT_attempt02.txt)에 남아 있다.

DINO와 YOLO detector 결과를 각각 context로 넣는 경로도 동일한 세 번의 생성 제한 이후 완전 응답을 받지 못했다. [grounding_dino/RESULT.md](03_end_to_end/grounding_dino/RESULT.md)와 [grounding_dino/predictions.json](03_end_to_end/grounding_dino/predictions.json), [yolo_world/RESULT.md](03_end_to_end/yolo_world/RESULT.md)와 [yolo_world/predictions.json](03_end_to_end/yolo_world/predictions.json)은 각각 15건 모두 `FAILED`로 저장되어 있다. 두 경로 모두 결과를 날조하지 않았으며 source-specific parser 상태는 `NO_COMPLETE_RESPONSE`다.

## Detector 동의어 진단

[run_config.json](run_config.json)은 canonical, common_synonyms, extended_synonyms 세 vocabulary group을 정의한다.

- canonical: `manipulator`, `conveyor`, `mobile robot`, `pallet`
- common_synonyms: `robot arm`, `robotic arm`, `conveyor belt`, `industrial conveyor`, `AGV`, `robot vehicle`, `wooden pallet`, `industrial pallet`
- extended_synonyms: `industrial robot`, `industrial robot arm`, `robotic manipulator`, `belt conveyor`, `AMR`, `mobile robot platform`, `cargo pallet`

진단 기준값은 YOLO confidence `0.02`, YOLO IoU `0.5`, DINO box/text threshold 각각 `0.15`, reference IoU `0.3`, wrong-label IoU `0.5`다. DINO와 YOLO confidence는 서로 다른 척도이므로 직접 비교하지 않는다. YOLO 입력 크기는 1280, 최대 검출 수 100이다. DINO/YOLO 각 trial의 detection 원문과 박스는 [vocabulary_trials_dino.json](detector_diagnostics/vocabulary_trials_dino.json) 및 [vocabulary_trials_yolo.json](detector_diagnostics/vocabulary_trials_yolo.json)에 있다. [vocabulary_trials.json](detector_diagnostics/vocabulary_trials.json)은 통합 trial 결과를 저장한다.

[detector_cross_comparison.json](detector_diagnostics/detector_cross_comparison.json)은 동일한 세 vocabulary group에 대한 detector 동작을 비교한다. 객체군별 결과는 다음과 같다.

| 객체군 | DINO 검출 건수 | YOLO 검출 건수 | 최고 cross-detector bbox IoU | 분류 |
|---|---:|---:|---:|---|
| manipulator | 27 | 1 | 0.2908509403 | VOCABULARY_DEPENDENT |
| conveyor | 17 | 4 | 0.9595810300 | AMBIGUOUS |
| mobile_robot | 11 | 21 | 0.9485708693 | VOCABULARY_DEPENDENT |
| pallet | 18 | 5 | 0.9590210841 | VOCABULARY_DEPENDENT |

해당 통합 파일의 best match 정보는 manipulator에서 DINO `d_013` (`industrial robot robotic manipulator`, extended)와 YOLO `y_014` (`industrial robot arm`, extended), conveyor에서 DINO `d_008` (`conveyor belt wooden pallet`, common)와 YOLO `y_007` (`belt conveyor`, extended), mobile_robot에서 DINO `d_003` (`robot vehicle`, common)와 YOLO `y_019` (`mobile robot platform`, extended), pallet에서 DINO `d_017` (`pallet`, canonical)와 YOLO `y_011` (`cargo pallet`, extended) 조합이다. 이것은 동일 이미지에서 vocabulary에 따른 검출 행동을 기록한 값이지 precision/recall 또는 우열 점수가 아니다.

통합 진단 status는 [detector_diagnostics/RESULT.md](detector_diagnostics/RESULT.md)에 `PASS (behavior characterization; no accuracy claim)`로 기록돼 있다. canonical DINO 시각화에서는 잘못된 범주와 크게 겹치는 박스들이 보이며, synonym overlay에서는 일부 대상에 대해 이미지의 바닥·장비·주변 물체를 가로지르는 큰 박스가 다수 나타난다. [dino_canonical.png](detector_diagnostics/overlays/dino_canonical.png), [dino_common_synonyms.png](detector_diagnostics/overlays/dino_common_synonyms.png), [dino_extended_synonyms.png](detector_diagnostics/overlays/dino_extended_synonyms.png), [yolo_canonical.png](detector_diagnostics/overlays/yolo_canonical.png), [yolo_common_synonyms.png](detector_diagnostics/overlays/yolo_common_synonyms.png), [yolo_extended_synonyms.png](detector_diagnostics/overlays/yolo_extended_synonyms.png)는 세 시험별 검출 박스를 보존한다.

세부 진단은 다음과 같다.

- Manipulator: 상태 `VOCABULARY_DEPENDENT`. 참조 영역 두 개 `q_030`, `q_031`은 Qwen 모델 출력이지 사람 ground truth가 아니다. Grounding DINO의 해당 위치 탐지는 canonical에서 `manipulator`, `manipulator mobile robot`, extended에서 `industrial robot robotic manipulator` 등으로 라벨이 바뀐다. DINO best reference IoU는 0.9074618183이다. baseline YOLO는 `q_030` 위치를 `cart`라고 분류했으나 IoU 0.9310548868로 위치는 거의 겹쳤다. baseline DINO도 `q_031` 위치를 `mobile robot`으로 분류했고 IoU 0.9127495620이다.
- Conveyor: 상태 `AMBIGUOUS`, 검토된 reference bbox가 없으며 expected region 및 best IoU가 null이다. DINO는 세 vocabulary에서 conveyor 관련 label을 내지만 일부 bbox가 넓은 바닥/다른 객체까지 포함한다. YOLO extended도 `belt conveyor`로 여러 물체를 검출했다. reference가 없으므로 위치 정확도나 어느 detector가 우월한지 결론내지 않는다. 세부 기록은 [conveyor_diagnostic.json](detector_diagnostics/conveyor_diagnostic.json)에 있다.
- Mobile robot: 상태 `VOCABULARY_DEPENDENT`. 참조 `q_029` 역시 Qwen output이지 ground truth가 아니다. 성공 label에는 `mobile robot`, `mobile robot platform`, `robot vehicle`이 있다. YOLO canonical best IoU는 0.9400909216이다. 반면 baseline YOLO는 같은 참조 위치를 `truck`으로 분류하고 IoU 0.9230502756, baseline DINO는 `workbench cart trolley`로 분류하고 IoU 0.9599356616이었다. 이는 localization보다 classification failure로 기록됐다. 세부 기록은 [mobile_robot_diagnostic.json](detector_diagnostics/mobile_robot_diagnostic.json)에 있다.
- Pallet: 상태 `VOCABULARY_DEPENDENT`. 참조 세 pallet bbox `q_002`~`q_004`도 Qwen model outputs다. DINO canonical `pallet` 및 synonym trial에서 reference 위치와 겹치는 여러 bbox가 나타나며, 통합 기록상 최고 reference IoU는 0.8135674931이다. baseline YOLO는 같은 위치들을 cardboard box, truck, storage rack 등으로 라벨링한 사례가 기록되어 있다. 세부 기록은 [pallet_diagnostic.json](detector_diagnostics/pallet_diagnostic.json)에 있다.

YOLO 진단 실행 환경은 NVIDIA GeForce RTX 5070 Ti Laptop GPU, CUDA 사용, torch `2.13.0+cu130`, ultralytics `8.4.164`다. 기록된 실행 시간은 `7.315364285999976`초다.

## 오류 분석과 비교 가능 범위

[06_error_analysis/RESULT.md](06_error_analysis/RESULT.md)는 오류 상태를 `PARTIAL`로 기록한다. taxonomy는 `DETECTION_FAILURE`, `CLASSIFICATION_FAILURE`, `RELATION_FAILURE`, `SEMANTIC_INFERENCE_FAILURE`, `TARGET_GENERATION_FAILURE`, `AMBIGUITY_HANDLING_FAILURE`다. 확인된 오류는 q_030/manipulator 위치가 YOLO에서 cart로, q_029/mobile_robot 위치가 YOLO에서 truck으로 나온 두 classification failure다. q_030 위치의 baseline YOLO IoU는 0.9311, q_029 위치는 0.9231로 기록되어 있어 위치를 못 찾은 문제와 label을 틀린 문제를 분리했다.

relation, semantic region, target 및 abstention의 정오 판단은 human ground truth가 없어 모두 `BLOCKED_BY_GROUND_TRUTH`다. TYPE_C Work Area 비교에서도 structured-context C03은 Loading Area를 출력했고 source-specific Qwen/DINO/YOLO는 모두 generation block 상태다. diagnostic augmentation이 Work Area output을 바꿨는지 여부는 null, 비교 상태는 `BLOCKED_BY_QWEN_SOURCE_SPECIFIC_GENERATION`이다.

ground truth가 없어 계산을 보류한 지표는 Spatial Relation Accuracy, Semantic Region Classification Accuracy, Semantic Region IoU, Instruction Grounding Success Rate, Goal-in-Region Rate, Abstention Precision, Abstention Recall이다. structured-context 응답 수나 영역 분포는 산출할 수 있지만 맞았다는 비율은 아니다. 세 source-specific 경로가 전부 실패이므로 cross-source semantic agreement도 평가 불가다. 상세 집계와 task별 비교는 [error_analysis.json](06_error_analysis/error_analysis.json)에 있다.

## 후속 실험 계획

[ABLATION_PLAN.md](08_future_experiments/ABLATION_PLAN.md)은 이번 실행에서 ablation 성능값을 보고하지 않았다고 밝히고 다음 조건을 제안한다.

1. object only, object+spatial relation, object+relation+semantic reasoning.
2. Qwen-only, Grounding DINO/SAM2-assisted, YOLO-World/SAM2-assisted.
3. color-rich와 monochrome.
4. original과 rearranged layout.
5. full과 partial semantic cues.

각 비교는 고정된 test set과 사람이 검토한 objects, relations, region boundaries, abstention labels, valid target regions를 필요로 한다.

[FUTURE_SEMANTIC_SCENE_PLAN.md](08_future_experiments/FUTURE_SEMANTIC_SCENE_PLAN.md)은 장면 A~E를 제안한다. A는 truck/racks/pallets/workbench/robot arms/conveyor/cart/drums/mobile robot가 포함된 baseline이다. B는 object identity, camera를 유지하고 Loading/Storage/Work/Material 위치를 교환해 절대 위치 shortcut을 시험한다. C는 같은 geometry를 유지하면서 색상 단서를 바꾸거나 monochrome/white printed object로 만들어 color shortcut을 본다. D는 truck에서 pallet을, manipulator에서 conveyor를 각각 제거하여 semantic cue 감소 및 abstention을 본다. E는 pallet/rack/drum을 반복 배치해 동등 후보를 만들고 nearest/between 지시의 referent disambiguation을 시험한다. 모든 장면에서 object box, relation, region polygon, mask, valid target과 각 계획별 presence/absence 및 intended referent 주석이 필요하다.

실행 보고서의 현 우선순위는 사람 검토로 15개 task 및 conveyor 후보 detection을 확인하고, 검토된 annotation으로 막힌 semantic/abstention metric을 다시 계산하며, 위치·색상·cue-removal·ambiguity shortcut을 시험하도록 Scene B~E를 촬영하고, 실제 카메라 geometry로 homography/target validation을 반복하는 순서다. 실물 로봇 dry-run이나 motion 전에는 undistorted fixed-camera frame, holdout floor correspondence, objects/relations/regions/masks/valid targets 주석, frozen prompts 및 thresholds가 요구된다. 기존 최종 상태 기록은 [SEMANTIC_REASONING_RUN_REPORT.md](SEMANTIC_REASONING_RUN_REPORT.md)에 있다.
